A tour of Pagda

Ten short programs. Each was run to build this page, and the panel under it shows what pagda printed. Every file starts with the two lines from Get started; the Copy button includes them.

An ordinary program

A checked file looks like typed Python. Every def says what it takes and what it gives back. A class with fields is a @dataclass.

{{run:t01_hello}}

Two number types appear here. int is any whole number. Nat is 0, 1, 2 and up, the type of counts and positions. A Nat is accepted wherever an int is wanted.

Things that can fail

Reading xs[i] fails when i is past the end. Dividing fails when the divisor is 0. In a checked file each of these needs a reason it is fine, and the usual reason is a test you would write anyway.

{{run:t03_bounds}}

The checker reads the tests. Inside if i < len(xs): it knows the index is good. Inside if xs: it knows the list is not empty, so its length is not 0. In the while loop, the second part of the and relies on the first, as it does in Python.

None

Optional[T] is a value that is a T or None. To use it as a T, test it first. After if found is None: return ..., the name holds a plain value.

{{run:t04_none}}

The second def never writes Optional for best. A local that is None in one place and a value in another is an Optional.

Changing a list

append, xs[i] = v and the other in-place changes work on a list the function made itself.

{{run:t05_change}}

A list that came in as a parameter belongs to the caller too. Changing it in place would change what the caller sees, so it is refused. Copy it first with list(xs).

{{refuse:t05_change_bad}}

Loops

A for loop needs nothing extra. A while loop has to end, and the checker sees that by itself for the two commonest shapes: a count going up to a limit, and a count going down to 0.

{{run:t06_loops}}

Any other while loop ends with decreases(measure, proof), which names a number that gets smaller on every pass. Proofs shows one.

Values in types

This is where Pagda goes past ordinary type checkers. A type can mention a value. Vec[A, n] is a list of exactly n items, and dot takes two vectors of the same length.

{{run:t07_vec}}

The second match has only one case. The checker knows b has the same length as a, so when a is a Cons, b is one too. Give dot vectors of different lengths and the file is refused:

{{refuse:t07_vec_bad}}

Proofs

A return type can be a statement. add(n, 0) == n as a type means "a proof that add(n, 0) equals n". The body builds that proof, and a recursive call plays the part of the induction step.

{{run:t08_proof}}

An assert at the top level is worked out by the checker before the program runs. A false one is a type error.

Asking the caller for a reason

A def can take a proof as a parameter. at reads xs[i] with no test of its own, because its third parameter is a proof that i is in range. The caller gets that proof from its own test with known(...).

{{run:t09_param}}

A caller with no reason is refused:

{{refuse:t09_param_bad}}

Holes

Write hole() for a part you have not worked out. The checker checks everything else, then says what the hole needs and what is in scope there.

{{refuse:t10_hole}}

The outside world

A checked file cannot open files or call libraries the checker has not read. A def marked @trusted is the door. The checker reads its annotations and believes them.

{{check:t11_trusted}}

Checked files can also import each other: from shapes import Point, width.
