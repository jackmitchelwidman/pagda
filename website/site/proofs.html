Proofs

In Pagda a type can be a statement, and a value of that type is a proof of it. This page shows how to state a fact and how to prove one, in Python syntax.

Statements as types

In an annotation, a == b is the type of proofs that a equals b. refl() is the proof that a thing equals itself. The checker works both sides out, so refl() proves any equation whose two sides come to the same thing.

add_zero has two cases. When n is 0, both sides work out to 0 and refl() is enough. Otherwise the recursive call proves the fact for n - 1, and cong(suc, ...) adds one to both sides of it. The checker also makes sure the recursion ends, which is what makes this a proof for every n.

Tests teach the checker

Inside if c: the checker replaces c by True in what is left to prove, and by False in the other branch. So a proof about a function that tests a < b can test a < b itself and finish each branch separately.

Or[A, B] is declared in the file: a proof of A or a proof of B. Inside a type, write Eq[x, y] for the statement x == y.

Getting the proof of a test

A test also gives a proof you can pass on. Inside if c: or while c:, known(c) is the proof that c is true. In the else part, known(not c) is the proof for the other way.

A parameter whose type is c == True works the other way round: inside the def, the checker treats c as known.

Impossible cases

Some types have no values. Fin[n] is a number below n, so Fin[0] is empty. A match on such a value has nothing to handle, and case _: return unreachable() says so. The checker accepts it only when it can see that no value gets there.

lookup has no case for an empty vector. An index of type Fin[n] into a Vec[A, n] cannot be out of range, and the checker sees that the missing case cannot happen.

While loops

A while loop outside the two shapes the checker handles by itself ends with decreases(measure, proof). The measure is a Nat worked out from the loop's variables. The proof shows that the measure at the end of a pass is smaller than it was at the start.

Here the measure is left itself. was remembers its value at the start of the pass, known(0 < was) is the loop's own test, and down_step turns those into the proof.

Working with holes

Proofs are written a piece at a time. Put hole() where you are stuck and run the checker. It reports the type the hole needs and the names you can build it from.

Here the hole needs n₁ + 0 ≡ n₁, where n₁ is n - 1. That is the fact itself for a smaller number, so the answer is the recursive call plus_zero(n - 1).

What proofs cannot reach yet

  • A property of a loop's result. Write the loop as a recursive def to prove something about it.
  • Types of types beyond the first level. A constructor field cannot hold a type.
  • Explicit type arguments at a call. The checker always works them out.
